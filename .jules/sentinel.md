## 2026-09-30 - [Stored XSS via innerHTML reflection]
**Vulnerability:** A Stored XSS vulnerability in `js/app.js` within the `entryHTML` function. User-supplied data (potentially from a malicious imported PDF via `import-cv.js` or directly from `localStorage`) was being rendered directly into HTML form inputs and textareas using template literals and injected via `innerHTML` without appropriate sanitization/escaping.
**Learning:** Even though this is a client-side only application (data is stored in `localStorage` and not a server database), it remains vulnerable to Stored XSS. If a user imports a crafted PDF, the data could execute malicious scripts within their session. Directly concatenating user data into strings intended for `innerHTML` is inherently dangerous, even for seemingly innocuous form field values.
**Prevention:** Always escape user-supplied data before inserting it into the DOM, especially when using `innerHTML`. The `esc()` function (which replaces `&`, `<`, `>`, `"`) should be applied to all dynamic content interpolated into HTML strings. Using properties like `textContent` or `value` on DOM elements is safer than string manipulation for `innerHTML`.
